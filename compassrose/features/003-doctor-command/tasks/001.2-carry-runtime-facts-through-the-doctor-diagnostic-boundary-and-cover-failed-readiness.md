## Task ID
`F003-T01-C02`

## Parent Task
`F003-T01`

## Parent Feature

## Goal
Update the existing Doctor diagnostic boundary so it receives the runtime facts already computed by doctorCommand.ts, preserves the existing DoctorReport metadata, and verifies readiness for an ordered failing check.

## First Executable Step
Add failing tests under tests/doctor/ for the existing repositoryRoot, currentPlatform, and configPath runtime facts and for DoctorCheckContext.readiness becoming false when its ordered checks contain a failure.

## Minimum Progress Evidence
- A test under tests/doctor/ fails before the implementation change because the context does not expose the existing runtime facts or failed readiness result.
- A source diff under src/doctor/ updates DoctorCheckContext/createCheckContext/buildDiagnosticReport and doctorCommand.ts to pass through the existing runtime facts without adding configuration parsing or new checks.
- Tests demonstrate that the normalized configuration remains unchanged and that check name, status, details, ordering, report metadata, success, and exitCode are preserved.

## Review Findings
- createCheckContext and buildDiagnosticReport omit the existing runtime facts repositoryRoot, currentPlatform, and configPath, forcing doctorCommand.ts to patch null placeholders after the boundary call.

- DoctorCheckContext.readiness is covered for ordered all-pass and pass/fail checks, while report aggregation preserves checks in order and derives exitCode 0 only when every check passes, otherwise 1.
- Tests under tests/doctor/ verify configuration non-mutation and runtime-fact/report preservation.
