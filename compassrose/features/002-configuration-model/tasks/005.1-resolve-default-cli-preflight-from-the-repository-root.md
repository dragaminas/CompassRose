# Task 005.1: Resolve default CLI preflight from the repository root

## Task ID
`F002-T05-C1`

## Parent Task
`F002-T05`

## Parent Feature
`002-configuration-model`

## Goal
Make `main([])` resolve the repository root before loading `docs/compassrose/CONFIG.md`, so the default CLI preflight works from nested directories inside the repo.

## First Executable Step
Import the existing Git-root lookup in `src/cli/main.ts` and replace the raw `cwd` config lookup with repository-root resolution before calling `readProjectConfiguration().

## Minimum Progress Evidence
- A regression test invokes `main([])` from a nested subdirectory inside a temp repository and still uses the root `docs/compassrose/CONFIG.md`.
- The nested-directory test covers both the passing preflight and at least one runtime-precondition failure.
- `main(['doctor'])` remains untouched and still routes to the existing doctor command.

## Review Findings
- The default CLI preflight still reads CONFIG.md from `cwd`, so `main([])` fails from nested repository directories and misses the repository-root requirement.

## Scope
Allowed:
- `src/cli/main.ts`
- `tests/main.test.ts`

Forbidden:
- `docs/`
- `src/contracts/`
- `src/doctor/`
- `src/config/`
- `src/git/`
- `proto/`

## Constraints
- Preserve the current doctor subcommand behavior.
- Do not add new configuration fields or change the config schema.
- Keep the change limited to runtime entrypoint path resolution and its regression coverage.

## Acceptance Criteria
- `main([])` resolves the repository root before reading `docs/compassrose/CONFIG.md`.
- Invoking the CLI from a nested directory inside the repo still loads the same project configuration and returns the same preflight result.
- The existing execution-, role-, and git_policy-based diagnostics remain unchanged.
- `main(['doctor'])` behavior remains unchanged.
