## Goal

- Replace the generic all-completed fallback with a deterministic no-selectable-feature message and add meaningful test coverage for these branches.

## Constraints
- Preserve existing repository, configuration, platform, role, Git preflight diagnostics, and main(['doctor']) routing.
- Run feature selection only after all preflight checks, including git_policy, pass.
- Derive request_pending only when request.md exists and one or more of feature.md, architecture.md, or state.md is missing; otherwise use ## Lifecycle State.
- Treat missing or unknown lifecycle data as a deterministic runtime feature-selection diagnostic with non-zero exit.
- Do not execute tasks, invoke roles or adapters, mutate feature state, or add provider-specific behavior.
- Do not modify documentation, contract files, or runtime state bookkeeping.

## Acceptance Criteria
- A dirty worktree with a selectable feature fails with the existing runtime preflight git_policy diagnostic and does not emit a feature-selection success message.
- A request.md folder missing one or more required formalized files is selected as request_pending according to the feature-state contract.
- A numbered feature with missing lifecycle data when request_pending does not apply, or with an unknown lifecycle value, exits 1 with a runtime feature-selection diagnostic and no success message.
- When all discovered features are completed, the CLI exits 0 with a deterministic no-selectable-feature message and does not select a feature.
- The existing completed-then-formalized happy path, main([]) preflight failure coverage, and main(['doctor']) regression coverage continue to pass.
